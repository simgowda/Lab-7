I would choose **1. Within a Github action that runs whenever code is pushed.** This would be the best place to fit automated tests because in this case the tests will be run consistently for every change made to the code regardless of the developer or the environment. By running tests so consistently, bugs can be caught early and often, so that project development can run smoother.

# 2.
I would not use an end-to-end test to check if a function is returning the correct output, because end-to-end tests are meant to test the behavior of the entire application from the user's perspective, simulating user interactions like clicking/navigating. In this way it would be better to use a unit test to test the behavior of a specific function.

# 3.
Navigation mode analyzes a webpage as it loads and measures overall page performance, runtime behavior, and loading speed during navigation. Snapshot mode analyzes only the current state of a webpage and is used to catch accessibility and structual issues instead of things like javascript performance.

# 4.
1. Get rid of/minimize unused or excess code (javascript and css) so that the site may load faster.
2. optimize the images to improve page load performance.
3. add better alternate text to images, color contrast, and other features to improve accessibility.
